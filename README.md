# DnsParse

  这是一个自动通过站长之家DNS解析工具检测本地区本网络对目标域名解析，并把解析记录保存至本机hosts和路由器etc/hosts，以加速github、steam、tinymediamanager、microsoft、gog、ubisoft、ea、origin等常见访问不稳定的国外地址。
  
  你也可以根据自己的需求自定义要解析的域名。

一、介绍

运行后，程序会：
  - 在本文件夹生成 hosts 和“解析报告.txt”；
  - 写入本机系统 C:\Windows\System32\drivers\etc\hosts，只改动脚本管理的域名，本机原来hosts里的内容不做任何修改并保留至文段最后；
  - 通过 SSH 把同一份管理块同步到路由器的 /etc/hosts。
    我使用的是openwrt作为软路由，其他路由器请自行开启ssh。

二、使用方式

  使用前安装 Node.js 22+，或确认 node.exe 在 PATH 中。也可以指定：DnsParse.ps1 -NodeExe "C:\（自定义路径）\node.exe"
  1. 打开本文件夹，双击“一键解析DNS.bat”，也可以把文件夹内的“一键解析DNS.bat”发送到桌面快捷方式。
  2. 程序会自动：
     - 读取 domains.txt；
     - 调用 chinaz-vote.js 查询站长之家；
     - 统计各监测节点的 IP 数；
     - 对最高及候选地址做 TCP 443 测速与 TLS 证书校验；
     - 每个域名取票数最高的多个 IP（默认 3 个）；
     - 生成 hosts 和“解析报告.txt”，按 domains.txt 分类分组；
     - 合并本机系统 hosts（不生成备份）；
     - 通过 SSH 合并路由器 /etc/hosts（不生成备份）；
     - 执行 ipconfig /flushdns 刷新本机 DNS 缓存。
  3. 不需要手动合并 hosts，运行完成后自动把解析好的域名写入系统 C:\Windows\System32\drivers\etc\hosts 和路由器 /etc/hosts。
  4.如需同步至路由器，请在运行前进行配置：
     -双击“配置路由器SSH.bat”；
     -按提示输入一次路由器密码；
     -看到“配置成功”后，后续运行会自动同步。

三、修改要解析的域名

  用记事本打开 domains.txt：
  - 一行一个域名，例如：

        github.com
        api.github.com
  - 可以保留 [github]、[steam] 这样的分类标题。
  - 空行、# 开头的行会被忽略。
  - 也可以直接粘贴 hosts 行，程序只取域名部分。
  - 不支持通配符（例如 *.example.com），这种行会被忽略。
  - 重复域名会自动去重，报告中会显示重复条目数量。
  改完保存，再双击“一键解析DNS”即可。

四、本机系统 hosts 合并规则

  本机默认目标：
      C:\Windows\System32\drivers\etc\hosts
  每次运行按以下顺序处理：
  1. 删除上一次写入的标记块：
         # >>> DnsParse managed block >>>
         ...
         # <<< DnsParse managed block <<<
  2. 扫描其余内容：
     - 以 # 开头的注释、空行原样保留；
     - 脚本管理的域名从映射行中删除；
     - 非管理域名保留；一行有多个主机名时，只删除管理项；
     - 如果一行里的主机名全部被删除，就删除这条映射，行尾的
             # 注释保留为独立注释行。
  3. 把纯 ASCII 管理块放在文件最前面（只包含 IP 和域名，不含
     中文注释），再把上面保留的原 hosts 内容整体放到管理块之后，
     即文件最下面。
  4. 确认文件没有被其他程序改动后，用临时文件原子替换；
     如果检测到并发修改，会重试一次，仍变化则放弃写入。
  5. 执行 ipconfig /flushdns 刷新 DNS 缓存。
    管理域名包括 domains.txt 中全部有效域名（包括本次解析失败和阻断的域名，用于清掉旧记录），以及本次实际写入的域名。
  路由器同步规则：
  - 先读取路由器当前的 /etc/hosts；
  - 删除旧的 DnsParse 管理块，再按域名过滤脚本管理的条目；
  - 路由器自己的 127.0.0.1 localhost、主机名、注释等非管理行保留；
  - 纯 ASCII 管理块放在文件最前面，路由器原有非管理内容放到最后；
  - 上传优先用 scp；路由器没有 scp/sftp 时自动改用 ssh 管道；
  - 写入后重新读取路由器 hosts，校验管理块条数；不一致视为失败。

五、状态说明与常见问题

状态：
  - 可达：最高票或候选地址通过 TCP 443，已写入 hosts；
  - 阻断：有票数，但最高票及候选地址在超时内都无法完成 TCP 443；
          这是网络层拦截，hosts 无法修复，建议使用代理、加速器或镜像；
  - 解析失败：站长之家没有返回有效 IPv4，或域名本身没有结果。
  1.某些域名显示“阻断”？
    说明站长之家返回了 IP，但本机到这些 IP 的 443 端口不通。地址不会写入 hosts，避免把污染或失效地址固定下来。换网络、代理或镜像源通常比改 hosts 更有效。
  2.某些域名显示“解析失败”？
    站长之家没有返回可用 IPv4，或域名已停用/写错。该域名不会写入   hosts，不影响其他域名。
3.访问又不稳定了？
  CDN 和投票结果会变化。换网络、重启路由器或过一段时间后重新双击运行一次即可。
4.需要管理员权限吗？
  解析、生成文件和同步路由器不需要管理员权限；更新系统 hosts 和刷新 DNS 缓存需要。双击“一键解析DNS.bat”会自动请求 UAC；点“否”时仍会生成 hosts 和报告，但不会修改系统 hosts，退出码 3。直接右键运行 DnsParse.ps1 不会自动提权。
